# SpriteMind — Local AI Pixel Art Generator & Research Platform

SpriteMind is an experimental, custom-trained machine learning research platform designed specifically to understand, construct, inspect, animate, and compose pixel-art game assets.

SpriteMind is **NOT** a wrapper around conventional diffusion models or external cloud APIs. Instead, it features an original, locally trainable neural architecture — **SVAN (SpriteMind Visual-Action Network)** — that creates pixel art through discrete drawing actions in a specialized domain-specific language (**PixelScript**), observes its own rendered canvas, detects anatomical defects with an autonomous critic, and articulates characters across animation sequences and equipment compositions.

---

## Key Capabilities (Stages 1–5.5)

- **Discrete Drawing Action Generation:** Generates 2D game characters via autoregressive token prediction over a virtual raster canvas.
- **Topological Visual Intelligence & Critic:** Detects stray pixels, interior voids, dislocated limbs, and palette leaks with autonomous closed-loop self-correction.
- **Recurrent Temporal Intelligence:** Predicts continuous kinematic trajectories $(\Delta x, \Delta y, \Delta \text{rot})$ across 20 animation categories (Basic, Combat including cast and dash, Creature gaits).
- **Multi-Layer Asset Composition:** Trainable `SocketPredictor` network (619K params) predicts sub-pixel equipment attachment sockets (`hand_r`, `head`, `back`) with dynamic multi-frame animation synchronization.
- **Prompt-Driven Action Sets:** One prompt becomes a coherent animation package — archetype, element and weapon are inferred from the text, then idle, movement, attacks, cast, dash, defense and death are rendered from a single shared character program with element FX (`POST /api/action_set`, new **Action Sets** tab). Sets can be generated facing right or left, mirrored at the script level so both sides of a platformer match exactly. Body build follows the prompt too: the planner infers a proportion (standard, stocky, slender, chibi) and an accessory (helmet, cape, horns, wings, backpack, pauldrons), falling back to a seed-stable choice, so a seed field with a reroll button in the Action Sets tab turns one prompt into a family of distinct characters.
- **Connected Animation:** Every emitted frame is checked for silhouette islands; offsets that would tear a limb off are pulled back and offsets that keep more pixels are preferred, so no part vanishes between frames. Thin limbs swing without rotating, and rest poses are drawn from touching runs rather than diagonal 1 px lines. See [`docs/ACTION_SETS.md`](docs/ACTION_SETS.md#staying-connected-staying-varied).
- **Game-Ready Packaging:** 2D bin-packing texture atlas builder with UV coordinates, spritesheets, and complete ZIP game packs (verified with top-down shooter *Dead Zone*).
- **Auditable SQLite Data Management:** Relational catalog (`data/spritemind.db`) with strict data classification, trash lifecycle, zero-loss deletion gates, and verifiable backups.

## Machine Learning Architecture

```
+-----------------------------------------------------------------------------------------+
|                               SpriteMind Model Ecosystem                                |
+-----------------------------------------------------------------------------------------+
  1. SVAN Action Transformer (~2.3M parameters)    --> models/checkpoints/svan_checkpoint_best.pt
  2. Neural Visual Critic    (368K parameters)     --> models/checkpoints/visual_critic_best.pt
  3. TemporalSVAN Recurrent  (426K parameters)     --> models/checkpoints/temporal_svan_best.pt
  4. SocketPredictor Regress (619K parameters)     --> models/checkpoints/socket_predictor_best.pt
```

All models are trained for **CPU-first deterministic execution** on consumer hardware (Intel Core i7-12650HX) with optional CUDA support.

## Strict Data Classification & Lifecycle Guarantee

SpriteMind enforces a non-negotiable boundary between protected core assets and disposable user files:

- **Tier A (Protected Training):** `data/datasets/`, `data/temporal_dataset_1k/` (IMMUTABLE).
- **Tier B (Protected Models):** `models/checkpoints/*.pt` (IMMUTABLE).
- **Tier C (Protected Research):** `docs/research/`, `data/benchmarks/` (IMMUTABLE).
- **Tier D (User-Generated Assets):** `data/assets/`, `data/asset_packs/` (DELETABLE via soft trash).
- **Tier E (Temporary Data):** `data/cache/`, `data/trash/`, caches (CLEANABLE).

> **CRITICAL GUARANTEE:** Deleting user-generated assets or emptying trash **NEVER** touches, corrupts, deletes, or retrains model checkpoints or training datasets.

## Quickstart & Local Setup

### 1. Prerequisites
- Python 3.10 or 3.11
- Node 18+ (only to build the web studio)

### 2. Install
```bash
python -m venv .venv && . .venv/bin/activate    # Windows: .venv\Scripts\activate
pip install -r backend/requirements.txt
cd frontend && npm ci && npm run build && cd ..
```

### 3. Launch
```bash
python backend/run_server.py        # Windows shortcut: .\start.ps1
```
Open **`http://127.0.0.1:7860`**. The same server exposes OpenAPI docs at `/docs`.
The API boots without the web bundle; `/` then prints the build command instead of
serving a blank page.

Configuration is environment-driven (see `.env.example`): `HOST`, `PORT`,
`SPRITEMIND_THREADS`, `SPRITEMIND_CORS_ORIGINS`.

### 4. Verify
```bash
pip install -r backend/requirements-dev.txt
pytest                      # configured in pyproject.toml, runs from any directory
ruff check backend          # lint (or: uvx ruff check backend)
```

### 5. Frontend Development
```bash
cd frontend
npm run dev     # hot-reload dev server on :5173, proxies /api to :7860
npm run build   # production bundle in frontend/dist, served by the backend
```

The web studio ships tabs for generation, animation, **composition** (equipment sockets and layered assets), dataset management, model lab and evaluation. `frontend/dist/` is build output and is not committed — build it before launching the studio.

### 6. Checking a Change
```bash
./scripts/check.sh                      # ruff, pytest, README metrics, frontend build, quality gate
SKIP_QUALITY_GATE=1 ./scripts/check.sh  # same, minus the generation sample
python scripts/quality_gate.py --limit 12 --engine trained_model   # generation only
```
The quality gate samples held-out prompts and fails when validity, palette adherence, engine honesty, silhouette fill or critic-clean rate regress, so renderer and training changes cannot slip in silently. `.github/workflows/ci.yml` runs the backend tests, the README metrics check and the frontend build on every push to `main` and every pull request.

### 7. Regenerating the Metrics Table
```bash
python scripts/update_readme_metrics.py           # rewrite the table below
python scripts/update_readme_metrics.py --check   # fail if it is stale
```
